# 支持接入本机部署的模型（Ollama / LM Studio 等）

## 需求

希望输入法的 AI 联想、候选词翻译等在线功能可以直接使用本机部署的模型，既能用上本地算力，也避免把输入内容发到云端。

常见方案是 Ollama（默认 `http://127.0.0.1:11434`），同类还有 LM Studio、vLLM、llama.cpp server，都提供 OpenAI 兼容的 `/v1/chat/completions`。

## 现状

当前版本**已经可以**通过「Custom」渠道接入本机服务，但有三个障碍，其中两个是代码问题。

### 1. 必须填一个无意义的 Token（代码问题）

发请求前会检查 Token 非空。Ollama 的本地 API 不做鉴权，收到 `Authorization` 头也是直接丢弃，所以这个 Token 只是为了通过本地检查。

填任意非空值（比如 `ollama`）即可绕过，但对用户来说是完全没有道理的一步。

### 2. 接口地址选错渠道会导致输出上限失效（代码问题）

在「OpenAI」渠道里填本机地址时，请求会带 `max_completion_tokens`。Ollama 的兼容层没有这个字段，会被静默忽略，配置的输出上限随之失效 —— 请求仍返回 200，界面上看不出任何异常。

改用「Custom」渠道可以避开发错字段，但用户无从得知这一点。

### 3. 超时偏短（待评估）

AI 联想默认 8 秒超时，语音润色 3 秒。本机模型首次请求需要加载权重，常常超出，表现为联想静默消失。

单纯调大数字会带来新问题：请求是同步阻塞的，worker 只有一条线程，一个慢请求会堵住后续所有输入。需要配合可中断机制一起做。

### 4. 云联想不可配置（独立问题）

「云联想」使用的接口地址是硬编码的，没有设置入口。与本需求无关，但如果目标是「所有在线功能都可离线」，这一项也需要处理。

## 建议

最小可用路径是修掉前两项：

- 地址指向本机（`localhost` / `127.0.0.1` / `[::1]`）时，Token 允许留空
- 输出上限字段按接口地址而不是渠道标签选择

局域网里的模型服务（`192.168.x.x` 等）建议维持需要 Token —— 公司环境下谁都能访问的裸 Ollama 不该被客户端当成免凭据服务。
