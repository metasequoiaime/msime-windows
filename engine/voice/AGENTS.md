# Shared VoiceInput

Reusable C++17 code is in `src/` with public headers in `include/msime/voice/`. The standalone Windows host in `platforms/windows/` must not enter the public targets. The host owns microphone permission, hotkeys, UI, token storage, threading, and committing text; for this product the host is `server/`.

Build `cmake -S voice -B build-voice`, then build and run CTest. Capture is optional, and core engine builds must not acquire voice dependencies. Local Whisper recognition was removed with the vendoring and stays out of this library. On-device recognition came back for users who cannot or will not send audio to a cloud provider, as a host feature: `server/src/voice-input/local_asr.*` loads a pinned sherpa-onnx runtime with `LoadLibrary`, and the runtime and models are downloaded on request by the settings window, never shipped or linked. The only file of it here is the vendored C API header in `third_party/sherpa-onnx/` (Apache-2.0, sherpa-onnx 1.13.8); update it together with the runtime pin in `server/src/voice-input/local_asr_catalog.h`, since the struct layouts must match the DLL. Public code uses `metasequoia::voice`, UTF-8 text and mono 16 kHz finite float PCM. Never open a microphone, send user audio or contact paid providers in automated tests; use synthetic samples and loopback HTTP fixtures.

Preserve imported history and licenses. Network code must release handles on success and failure, bound responses, check status, support cancellation and avoid logging response bodies or tokens. Audio device state is per instance. Start/stop are serialized by the host; callbacks must never call stop or destroy the capture object.
